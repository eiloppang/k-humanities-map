# KCI · KRI 데이터 수집 방법

> 한국 인문학 학술 지형도 구축 · 1차 분과 = **한국어와문학(A11 = KCI 분류코드 "인문학 > 한국어와문학")**
> 수집 대상 기간: 2008–2024 · 최종 갱신: 2026-06

두 종류의 데이터를 수집했다.
1. **KCI 논문·인용 데이터** — 한국어와문학(A11) 논문의 서지·초록·인용현황(참고문헌+피인용)
2. **KRI 연구자정보** — 그 논문 저자들의 소속·직급·전공·학위

---

## 1. KCI 논문·인용 데이터 수집

### 1.1 대상
- KCI 「인문학 > 한국어와문학」(A11) 전체 학술지 **115종**, **52,068편** (2008–2024)

### 1.2 수집 방법 — `scrape_korlit.py`
KCI는 참고문헌·피인용 목록을 **로그인 후에만** HTML에 노출하므로 로그인 세션이 필요하다.

1. **로그인 (1회)** — Selenium으로 KCI 로그인 → 세션 쿠키(JSESSIONID 등) 추출.
2. **고속 수집** — 추출한 쿠키를 `httpx` + `ThreadPoolExecutor`(12스레드)에 이식해 멀티스레드로 상세페이지를 긁는다. (네트워크 I/O 바운드라 스레드풀이 적합)
3. **논문 열거** — 학술지명으로 검색하되, 결과 행의 `sereId`(학술지 고유 ID)가 목표와 일치하는 것만 취해 **동명이저널·유사명 저널을 정밀 필터**.
4. **상세 파싱** — 논문별로 다음을 추출:
   - 서지: 제목(국/영)·저널·발행기관·권호·페이지·DOI·ISSN·발행연월
   - 연구분야(논문 세부분류), 저자(국/영)·소속, 초록(국/영), 키워드
   - 피인용수·FWCI·열람수
   - **참고문헌(references)** `[{n, type, art_id, text}]`
   - **피인용목록(cited_by)** `[{art_id, crt_id, title, authors, journal, pub_date, pages, cited_count}]`
5. **재개(resume)** — 완료 레코드를 JSONL 체크포인트에 즉시 적재. 세션 만료(로그아웃) 감지 시 자동 재로그인.
6. **산출** — `korlit_2008_2024.pkl` / `.csv` (34개 컬럼).

### 1.3 cited_by(피인용) 데이터 정제 — art_id 기준 재도출
수집된 `cited_by`의 **저널명(`journal`) 칸이 오염**된 문제를 정제했다.

- **문제**: 다저자 인용 논문을 파싱할 때 칸 정렬이 밀려, **저널명 자리에 공저자 이름**이 들어갔다.
  (예: 저자 `최정선`, journal=`권미경` ← 권미경은 저널이 아니라 공저자)
  참고문헌(references)은 정상(art_id 대조 98.1% 일치) — **cited_by만** 문제.
- **진단**: cited_by 260,537개 항목이 **art_id 100% 보유** → 복구 가능. 내부 데이터로 대조한 **실측 오염률 13.4%**.
- **방법 (4단계)**:
  1. 진단·규모 산정 — 고유 art_id 85,376 (내부 35,287 / 외부 50,089)
  2. 내부 즉시 복구 — art_id가 코퍼스에 있으면 진짜 저널명 즉시 대입 (144,275칸, 55.4%)
  3. 외부 KCI 재조회 — 나머지 고유 art_id **50,089건**을 KCI 상세페이지로 조회(로그인 불필요), 캐시·재개
  4. 분과 매핑 — 확보한 저널명을 `학술지종수.xls`(KCI 전체 6,339종)에 **한글명·영문명·ISSN 다중키**로 매칭
- **원칙**: 원본 `journal`은 보존하고 `journal_clean`·`field_major`·`field_minor`·`resolve_src`를 **신설**.
- **결과**: 260,537 항목 **100% 분과 복원** (외부 분과 매칭률 100%, 재조회 실패 0).
- **산출**: `Data/new-results_(선영보낼것)/korlit_2008_2024_clean.pkl · .csv`

> ⚠️ 정제 후 "외부 분과가 인용한 A11 논문"은 32,220편으로 집계(기존 표기 774편). 과거 수치가 오염으로 대거 누락됐던 탓이며, "외부"의 정의(A11만 vs 어문/인문 계열 포함)를 함께 명시해야 한다.

## 2. KRI 연구자정보 수집

### 2.1 목표
논문 저자를 **국가연구자번호(kri_num)**로 식별해, KRI(한국연구자정보)에서
**성명·성별·소속대학/기관·직급·전공분야(세부전공)·출신학교·취득학위**를 수집. → 미포섭 분석(소속 분과 vs 출판 분과)의 기반.

### 2.2 kri_num 수확 (KCI 단계, 2FA 불필요)
**핵심 발견**: 국가연구자번호는 KCI 안에 있다.
- KCI 연구자 페이지(`poCretDetail`)의 onclick `fncArtiSelectCitationIdx('CRT…','<kri_num>')` — **두 번째 인자가 kri_num**.
- 우리가 이미 가진 각 논문의 `crt_id`(저자별 인용보고서 ID)로 이 페이지를 열면 kri_num을 얻는다. **KCI 자동 로그인만 필요(2FA 없음)**.

| 단계 | 스크립트 | 내용 | 결과 |
|---|---|---|---|
| 1a | `collect_crets.py` | 다저자 논문(5,177건) article 페이지 `div.author`에서 **전 저자 cretId** 수집 | 완료 / 실패 0 |
| 1b | `harvest_krinum.py` | 고유 cretId **16,195** → poCretDetail에서 kri_num 추출 | kri 10,092 / no_kri 6,103 / 오류 0 |
| 1c | `build_mapping.py` | (논문·저자·cret·kri_num) 매핑 테이블 | 59,552행 / **고유 연구자 8,511명** |

- **no_kri**: crt는 있어도 KRI 미등록이라 kri_num이 없는 연구자(6,103건)는 정상 케이스 → 별도 분기(오류 아님).
- 로그아웃 판정은 pairs 유무가 아니라 **페이지 크기**(로그아웃 셸 ~11KB vs 정상 ~60KB)로.

### 2.3 KRI 연구자정보 수집 (2FA 단계)
- **정답 페이지 = `PG-RP-102-02jr.jsp?txtRschrRegNo={kri_num}` (기본정보 조회)**.
  th/td 표에 7개 필드가 **실제 값**으로 들어 있다.
  (⚠️ 과거엔 `PG-RP-101`의 IBSheet 그리드를 긁어 **헤더 텍스트만** 따오는 버그가 있었음 — 본수집 전 셀 구조 덤프로 확정.)
- **로그인**: KRI는 2FA가 있어 자동화 불가 → **사용자가 브라우저 창에서 직접 로그인+2FA**, 그 세션을 스크립트가 인계.
- **세션 견고화 (밤샘 무인 수집)** — `collect_kri_overnight.py`:
  - 절전 방지(`SetThreadExecutionState`) — PC sleep → idle 로그아웃 예방
  - 연속 활동 — 쉼 없이 페이지 이동으로 idle 타임아웃 회피
  - 체크포인트/재개 — kri당 1줄 JSONL, 종결건만 skip
  - 세션 만료 감지 시 재로그인 대기 후 자동 재개
  - 페이지 30초 로드 제한 + 드라이버 죽으면 자동 재시작
  - 비공개(정보 공개 거부) 연구자는 alert 처리해 `private`로 기록
- **결과**: **8,511 / 8,511 (100%)** — 데이터 수집(ok) **7,883** / 비공개 628 / 오류 0.

### 2.4 산출물 — `build_final.py`
- `KRI/researchers.csv` — 연구자 1명/행 (8,511명, 7필드+상태)
- `KRI/author_paper_kri.csv` — 논문×저자 **59,552행**, 연구자정보 조인 49,408행 (분석 마스터)
- `KRI/kri_mapping.csv` — (논문·저자·cret·kri_num) 매핑

## 3. 핵심 기술 결정 · 교훈
1. **오염 복구의 열쇠는 art_id** — 오염된 문자열을 버리고 고유번호로 원천을 다시 조회.
2. **kri_num은 KCI 안에 있었다** — 별도 조회 없이 crt_id→onclick에서 수확(2FA 회피).
3. **KRI 7필드의 정답 페이지는 PG-RP-102** — 과거 헤더만 따온 버그는 잘못된 페이지(PG-RP-101 그리드) 탓.
4. **2FA 사이트 무인 수집** — 수동 로그인 인계 + 절전방지·연속활동·재개·드라이버 자동복구가 필수.
5. **결측의 구조적 성격 명시** — kri 미등록(6,103) + 비공개(628)는 표본 편향으로 분석 시 명시.

## 4. 재현 순서 (요약)
```
# KCI 수집
python scrape_korlit.py                 # 논문·인용 원수집
# cited_by 정제 (문제점/ 폴더)
python 문제점/phase2_internal.py         # 내부 복구 + 외부 워크리스트
python 문제점/phase3_fetch_external.py   # 외부 art_id KCI 재조회
python 문제점/phase4_merge.py            # 분과 매핑·저장(clean pkl/csv)

# KRI 수집 (KRI/ 폴더)
python KRI/collect_crets.py             # 1a 다저자 공저자 cret
python KRI/harvest_krinum.py            # 1b kri_num 수확 (KCI, 2FA 없음)
python KRI/build_mapping.py             # 1c 매핑 테이블
python KRI/collect_kri_overnight.py     # 2  KRI 기본정보 수집 (2FA 수동)
python KRI/build_final.py               # 3  최종 병합
```
